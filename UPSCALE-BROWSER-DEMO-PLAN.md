# UpScale demo — управление через браузер, без API

**Решение пользователя от 11.11.2026:** не применять API для доступа к UpScale.
Целевая работа ассистента — анализировать графики и **самостоятельно вести
демосчёт через видимый пользовательский интерфейс UpScale**,
используя авторскую методику из репозитория
[`gurarino4ka-jpg/Gurman`](https://github.com/gurarino4ka-jpg/Gurman/tree/main/docs/course).

**Единственный разрешённый канал взаимодействия:** открытая пользователем
сессия облачного браузера в ChatGPT Work, если она доступна,
с действиями через GUI. Не использовать API, сетевые запросы к скрытым
эндпоинтам, автоматизированную отправку HTTP-заявок, не внедрять ключи,
не подключать расширения для обхода интерфейса.

## Состояние и доступность

- Приложение: https://app.upscale.trade/ . Вход выполняет пользователь
  самостоятельно, без передачи пароля/2FA ассистенту и без записи секретов
  в репозиторий.
- **В GitHub Actions нельзя авторизоваться и торговать.** CI тестирует только
  изолированный код на фиктивных данных.
- В обычном чате GitHub-коннектор может читать и изменять код, но не
  управляет окном UpScale. Для браузерных действий нужен режим Work с
  доступным облачным браузером. Наличие такого доступа не подтверждено.
- Не считать сохранённую авторизацию, размер баланса, список контрактов
  или тип счёта установленными до проверки в самом интерфейсе.
- Никаких live/real счетов, реальных денежных операций, пополнений,
  выводов, переводов или настроек платёжных средств.

## Последовательный сценарий в браузере

1. Открыть указанное приложение и проверить авторизацию. Если требуется
   вход или 2FA — передать действие пользователю, не запрашивая пароль.
2. **Сначала убедиться визуально, что выбран DEMO, а не live.**
   Зафиксировать название счёта, валюту, баланс, торговую платформу,
   ограничения проп-фирмы и доступные BTC, ETH, SOL, если отображаются.
   Если режим не доказан, остановиться без действий.
3. Осмотреть графики и инструменты исключительно через GUI. Сопоставлять
   наблюдения с методикой Gurman; отмечать дату/часовой пояс, таймфрейм,
   состояние свечи и источник цен. Не додумывать отсутствующие котировки.
4. Для каждого решения формировать торговый план: модель, контекст,
   ликвидность/sweep, структурный BOS/Shift, Order Flow/FVG/POI, SMT
   при применимости, направление, условие входа и отмены, стоп, цель,
   соотношение риска и прибыли. Отдельно отмечать несовместимые модели
   и незакрытые условия авторского курса.
5. Начать с **наблюдения и подготовки виртуальных планов без заявок**.
   Затем разрешать **демо-ордера внутри GUI**, только когда подтверждены
   видимый DEMO-режим, условия конкретного сетапа, размер позиции и
   согласованные лимиты риска. Пользователь уже выразил намерение
   делегировать управление демосчётом; это не разрешение на live.
6. После каждого решения записывать: время, инструмент, скриншоты графика
   и терминала, модель, причины входа/пропуска, цены, стоп, цель,
   объём, оценку риска, итог и ошибки. Не представлять выставленный,
   отменённый или неисполненный ордер как исполненную сделку.
7. Проверять ограничения UpScale в интерфейсе перед действиями.
   Любая неоднозначность авторизации, режима, лимита, котировки,
   подтверждения исполнения или рассинхронизация интерфейса — **STOP**.
   Не пытаться повторно отправлять заявку после сетевой ошибки,
   пока статус ордера не проверен визуально.

## Методика и границы подтверждённых правил

Источник правил — `Gurman/docs/course/lesson-01.md` …
`lesson-08.md`, сверки, реестр
`Gurman/docs/history/rules-register.csv`.

- Темы: ликвидность и структура, Order Flow, AMD и сессии, квартальная
  теория, SMT, фильтры TDO/Bias и конфигурации сетапов.
- В итоговом уроке есть различные конфигурации и **примеры** рисков:
  1% для live и 1,5% для prop. Эти числа **не являются согласованным
  пользовательским лимитом**. Раннее предложение GPT «0,25% на демо,
  максимум 1% в день, одна позиция» тоже не утверждено пользователем.
- Ряд точных условий (триггеры, стоп для некоторых FVG-сценариев,
  приоритет фильтров, границы сессий, комиссии, лот/контракт и
  ограничения совокупного риска) обозначен как непроверенный.
  Не подменять эти условия произвольными числовыми правилами и
  не выполнять сделку, если план нельзя однозначно воспроизвести.
- Макроэкономика и бэктесты не возобновляются автоматически.

## Что делать с предыдущими CA-60…CA-98

Модули `monitor/readonly-transport.mjs`,
`monitor/demo-account-reader.mjs`,
`monitor/demo-account-checkpoint-store.mjs`, связующие модули,
тесты и `npm run demo:verify` — это **прежний офлайн-прототип**
на синтетических данных. Они **не подключены к UpScale** и
**не являются путём реализации данного плана**. Не разрабатывать
для них UpScale-адаптер, не добавлять API-ключ или API-провайдера.
Можно оставить их изолированными как технические тесты, но
не отчитываться о них как о готовности браузерного управления.

## Дальнейшая цель

Первая реальная сессия в Work: проверить вход, тип счёта и графики,
заполнить наблюдаемый профиль демосчёта, начать журнал сигналов.
Подготовить практический демо-сетап и только после уточнения
исполнительных рисков проводить операции **в демосреде**.
Фоновая круглосуточная работа между сессиями не предполагается
и не обещается без отдельной поддерживаемой автоматизации.
