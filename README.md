# ТрейдЛаб — Практика

Русскоязычный учебный симулятор сделок с виртуальным балансом. Он помогает разобраться в направлениях long/short, стоп-лоссе, тейк-профите, комиссиях и ведении журнала. Отдельный локальный сборщик получает публичные рыночные данные UpScale/Bookflow. Подключения к торговому счёту и денежных операций нет.

## Локальный мониторинг рынка

Для Windows подготовлена [пошаговая инструкция](MONITOR-WINDOWS.md). Нужен Node.js 24 LTS или новее; внешние зависимости, регистрация и платный GPT API не нужны.

```sh
npm run monitor:once
npm run monitor
```

Сборщик проверяет BTC, ETH, SOL и ZEC каждые 60 секунд, сохраняет котировки, H1/M30/M15 и события закрытия свечей. Публичный источник показывает BASE/USD и рассчитывается в USD; его метаданные называют тикеры BASE/USDT. Незакрытые свечи отделены от завершённых, пропуски и устаревшие данные отмечаются явно. Первый запуск создаёт исходный снимок без выдачи исторических свечей за новые события. После перезапуска закрытые свечи не дублируются в журнале.

Настройки — `monitor.config.json`; состояние, журнал и снимки — `data/market-monitor/` (исключено из Git и не обслуживается веб-сервером симулятора). `monitor.lock` защищает от одновременного запуска. Ошибки записи или повреждённый журнал останавливают процесс. Сборщик не содержит алгоритма торговых сигналов, не авторизуется в аккаунте и не размещает заявки. Работает, пока программа и компьютер включены; автоматический запуск Windows не устанавливается.

## Запуск

Нужен Node.js 22 или новее; рекомендуемая версия 24 указана в `.nvmrc`. Внешних зависимостей нет. Из корня этого репозитория:

```sh
npm ci --offline --ignore-scripts --no-audit --no-fund
PORT=3001 npm start
```

Порт 3001 позволяет запускать симулятор одновременно с академией из **Gurman**, использующей порт 3000. Без `PORT` сервер выбирает 3000. По умолчанию он слушает только локальный интерфейс; для контейнера можно указать `HOST=0.0.0.0`.

Для разработки: `PORT=3001 npm run dev`. Клиентские изменения видны после перезагрузки страницы. Проверка готовности:

```sh
curl --fail http://127.0.0.1:3001/health
```

## Учебный сценарий

1. Изучите график синтетического инструмента и доступный виртуальный баланс.
2. Выберите направление, размер позиции, уровни стоп-лосса и тейк-профита.
3. Откройте сделку. Размер ограничен доступным капиталом; кредитное плечо не используется.
4. Переключайте свечи и наблюдайте за результатом или закройте сделку вручную.
5. Разберите результат в журнале, учитывая комиссию за вход и выход.

График генерируется локально и не соответствует котировкам какого-либо реального актива. Баланс, открытая позиция и журнал сохраняются в `localStorage` текущего браузера. Синхронизации и серверной базы данных нет. Сброс тренировки удаляет локальные результаты после подтверждения.

Симуляция упрощена: нет стакана, ликвидности, кредитного плеча, финансирования short-позиций и частичного исполнения. Направление short моделируется с резервированием виртуального капитала. Если в одной свече задеты стоп и цель, приоритет получает стоп — без тиков нельзя установить реальный порядок. Результаты такой тренировки не прогнозируют результат реальной торговли.

## Проверки

```sh
npm run check
npm test
```

Встроенный тестовый раннер Node.js проверяет торговую арифметику, обработку некорректных заявок, защитные уровни и HTTP-сервер. Сборка не нужна: используются нативные ES-модули. CI запускает проверки на Node.js 22 и 24.

## Непрерывная проверка безопасности демосчёта (CA-98)

Одна команда последовательно запускает проверки синтаксиса, GET-only транспорта,
валидации ответов, защиты от повторных снимков, файловой целостности, блокировок,
аварийного завершения дочернего процесса, восстановления после перезапуска
и локальный демонстрационный запуск. При первой ошибке процесс завершается
с ненулевым кодом. Ручное подтверждение между этапами не требуется.

```sh
npm run demo:verify
```

Чтобы посмотреть только демонстрационный пример счёта с виртуальным балансом:

```sh
npm run demo:smoke
```

Обе команды работают **исключительно с синтетическими данными**, не требуют API-ключей,
не обращаются в UpScale и не выставляют ордера. В GitHub Actions
`demo-readonly-gate` выполняет этот же непрерывный прогон на Linux с Node.js 22/24
и на Windows с Node.js 24.

**Реальный UpScale пока NO-GO.** Официальная документация
[Upscale Public API](https://docs.upscale.trade/developers) теперь содержит
`GET /accounts/with-risk-status` и `GET /v2/markets`.
Но API-ключ наследует права владельца, поэтому нельзя считать такой ключ
гарантированно read-only. До подключения нужны проверка прав доступа, отдельный
GET-only адаптер, реальный формат ответов и явное разрешение пользователя
на чтение демосчёта. Ключи запрещено сохранять в Git, CI, логи и чат.

## Устройство

```text
public/index.html     — интерфейс терминала
public/styles.css     — адаптивные стили
public/app.mjs        — график, формы и журнал
public/domain.mjs     — генератор свечей и движок симуляции
server.mjs            — статический HTTP-сервер и /health
tests/                — автоматические проверки
```

Для статического хостинга достаточно содержимого `public`; endpoint `/health` предоставляет сервер Node.js. Секреты и аккаунты не нужны. Парный репозиторий **Gurman / ТрейдЛаб — Академия** содержит уроки, тесты и калькулятор риска. Материалы и тренажёр предназначены для обучения, не являются инвестиционной рекомендацией.
